# Windows Defender SmartScreen 차단 해결 및 테스트 가이드

이 문서는 MyDiary Desktop 앱을 윈도우 환경에서 패키징하여 직접 설치/실행하거나 다른 테스터에게 전달하여 테스트할 때 발생하는 **Microsoft Defender SmartScreen (인식할 수 없는 앱의 시작을 차단했습니다)** 보안 경고를 해결하고 원활하게 테스트하는 방법을 안내합니다.

---

## 1. SmartScreen 차단이 발생하는 원인

윈도우(Windows 10/11)의 **SmartScreen**은 다운로드되거나 실행되는 새로운 `.exe` 파일에 대해 다음 조건일 때 파란색 경고 창을 띄웁니다:
1. **디지털 서명 부재**: 개발자/기업의 신뢰할 수 있는 코드 사이닝(Code Signing) 인증서로 서명되지 않은 경우.
2. **다운로드 평판(Reputation) 부족**: 바이러스나 악성코드가 아니더라도, 마이크로소프트 클라우드에 다운로드 및 실행 이력이 충분히 누적되지 않은 신규 파일인 경우.

> **참고**: 이는 프로그램의 오류나 악성코드가 아니라 윈도우의 정상적인 미확인 앱 보호 절차입니다.

---

## 2. 테스터 입장에서 즉시 실행하는 방법 (가장 간단)

인터넷(구글 드라이브, 카카오톡, 메일 등)으로 설치 파일(`MyDiary Setup 0.3.0.exe`)이나 포터블 파일(`MyDiary 0.3.0.exe`)을 받아 실행할 때 다음 2가지 방법 중 하나로 즉시 실행할 수 있습니다.

### 방법 A. SmartScreen 경고 창에서 바로 실행 (권장)
1. **"Windows의 PC 보호"** 파란색 경고 창이 나타납니다.
2. 본문 내용 중 밑줄 친 **[추가 정보]** 링크를 클릭합니다.
3. 앱 이름(`MyDiary`)과 게시자 정보가 나타나며, 우측 하단에 숨겨져 있던 **[실행]** 버튼이 활성화됩니다.
4. **[실행]** 버튼을 클릭하면 정상적으로 설치 또는 실행됩니다.

### 방법 B. 파일 속성에서 웹 다운로드 차단 해제 (Unblock)
인터넷 브라우저나 메신저로 다운로드한 파일은 윈도우에 의해 "외부에서 온 파일" 플래그(Zone.Identifier)가 붙습니다. 이를 사전에 해제할 수 있습니다:
1. `MyDiary Setup 0.3.0.exe` 파일 우클릭 → **[속성]** 메뉴 선택.
2. **[일반]** 탭 하단의 보안 섹션 확인:
   > *"보안: 이 파일은 다른 컴퓨터로부터 왔으며 이 컴퓨터를 보호하기 위해 차단되었을 수 있습니다."*
3. 옆의 **[차단 해제 (Unblock)]** 체크박스에 체크한 후 **[확인]** 클릭.
4. 이제 파일을 더블 클릭하면 SmartScreen 경고 없이 부드럽게 실행됩니다.

## 3. 개발자/사내 배포 시 자체 서명(Self-Signed) 패키징 방법

현재 프로젝트에는 자체 서명 코드 사이닝 인증서 생성 및 자동 서명 빌드 스크립트가 내장되어 있습니다.

### 실행 명령어
터미널에서 기본 패키징 대신 아래 명령어를 실행합니다:

```bash
npm run package:win:signed
```

### 작동 원리
1. **인증서 자동 생성 및 PC 신뢰 등록** (`scripts/create-cert.ps1`):
   - 5년 유효기간의 자체 서명 인증서(`certs/dev-cert.pfx`, 비밀번호: `mydiary1234`)를 생성합니다.
   - 현재 PC의 `신뢰할 수 있는 루트 인증 기관(Root)`과 `신뢰할 수 있는 게시자(TrustedPublisher)`에 자동 등록합니다.
2. **디지털 서명 패키징** (`scripts/build-signed.ps1`):
   - `electron-builder`에 생성된 인증서를 전달하여 `MyDiary.exe` 및 `MyDiary Setup 0.3.0.exe`에 디지털 서명을 입힙니다.
3. **효과**:
   - 인증서가 등록된 개발/테스트 PC에서는 "알 수 없는 게시자" 대신 **게시자: Sung Baekjin**으로 인식되어 SmartScreen 경고 없이 신뢰된 앱으로 실행됩니다.

> **팁**: 다른 테스터 PC에서도 동일하게 경고 없이 실행되도록 하려면, `certs/dev-cert.cer` 파일을 테스터 PC로 복사한 뒤 더블 클릭 → **[인증서 설치]** → 저장소 위치: **[로컬 컴퓨터]** → **[신뢰할 수 있는 루트 인증 기관]**에 한 번만 등록해 두면 됩니다.

## 4. 정식 상용 배포 시 완전한 해결 방법 (참고용)

불특정 다수의 일반 고객에게 배포할 때 경고를 완전히 없애려면 다음 방식을 채택합니다:

1. **공인 코드 사이닝 인증서(Code Signing Certificate) 도입**:
   - Sectigo, DigiCert, GlobalSign 등의 공인 인증기관에서 **개인/법인 코드 사이닝 인증서(OV/EV)**를 발급받습니다.
   - `build-signed.ps1`의 인증서 경로(`$certPath`)와 비밀번호만 실제 공인 인증서로 교체하면 자동으로 마이크로소프트의 공식 신뢰를 획득합니다.
2. **Microsoft Store(MS 스토어) 출시**:
   - MSIX 패키지로 변환 후 Microsoft Store에 등록하면, 스토어 자체 검증을 거치므로 SmartScreen 경고가 완전히 면제됩니다.

## 5. 요약 체크리스트

| 상황 | 추천 조치 방법 |
| :--- | :--- |
| **개발자 PC에서 바로 테스트할 때** | `npm run package:win:signed` 로 패키징 후 실행 |
| **테스터에게 exe 파일만 전달했을 때** | 테스터에게 **[추가 정보] → [실행]** 또는 **우클릭 속성 [차단 해제]** 안내 |
| **고정된 사내 테스트 환경 구성 시** | 테스터 PC에 `certs/dev-cert.cer` 인증서를 1회 설치 |
| **일반 사용자 공식 배포 시** | 공인 코드 사이닝 인증서(Sectigo 등) 구매 적용 또는 MS Store 출시 |
