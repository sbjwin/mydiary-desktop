# MyDiary Desktop 데이터베이스 무결성 & 백업 보호 (Database Integrity)

이 문서는 MyDiary Desktop 프로젝트에서 사용자 데이터의 보존과 모바일-데스크톱 상호 호환성을 보장하기 위한 데이터 무결성 규칙입니다.

---

## 1. 최우선 원칙: 데이터 무결성은 기능 구현보다 상위이다 (Never Lose User Data)
- 사용자의 성장 기록, 관찰 일지, 상담 메모는 교육 및 법적 증빙 자료로 활용될 수 있는 민감한 데이터입니다.
- 어떤 기능 추가나 리팩토링도 기존 저장된 데이터의 포맷을 깨뜨리거나 유실시켜서는 안 됩니다.

---

## 2. 모바일 백업 JSON 1:1 완벽 호환 원칙
- 스마트폰용 앱(`mydiary`)에서 내보낸 백업 JSON 파일은 데스크톱에서 100% 오류 없이 복원되어야 합니다.
- 데스크톱에서 내보낸 백업 JSON 파일 역시 스마트폰 앱에서 즉시 복원될 수 있도록 동일한 JSON 구조와 키 네이밍을 유지합니다.

---

## 3. 스토리지 키 및 스키마 규격
- **학생 목록**: `@mydiary:students`
- **일지/기록**: `@mydiary:records`
- **주간 계획표**: `@mydiary:weekly_plans`
- **모의 클라우드 스토리지**: `@mydiary:mock_cloud_storage`

---

## 4. 참조 무결성 및 연쇄 삭제 (Cascade Delete)
- 학생 정보가 삭제될 경우, 해당 학생과 연결된 모든 일지 레코드(`records`)와 주간 계획표(`weekly_plans`)가 누락 없이 안전하게 정리(Cascade Delete)되어 고아 데이터(Orphan Data)가 남지 않도록 보장합니다.

---

## 5. 안전한 쓰기 및 백업 보존
- 로컬 스토리지에 변경 사항을 쓸 때는 `try-catch`로 감싸고, 할당량 초과(QuotaExceededError)나 비정상 데이터 입력 시 즉각 사용자에게 친절한 인앱 안내를 제공합니다.
